# مهام KMT لتطوير مكونات الواجهة والحركة

تاريخ إضافة القائمة: 2026-09-13، بطلب المستخدم حفظ تفاصيل الواجهة والموشن ضمن مهام العمل.

هذه هي قائمة المتابعة التفصيلية للجزء البصري من خطة المراجعة والتطوير المعتمدة، وترتبط بخطوات المحتوى والتصور والمكونات والتطبيق والفحص النهائي (7–14). لا تستبدل مراجعة التشغيل والحماية الجارية، ولا تفعل Spec Kit. خطط الحركة القديمة المنفذة لا تعني اكتمال المهام الجديدة أدناه.

## طريقة المتابعة

- كل مهمة لها رقم ثابت. جميع المربعات أدناه مفتوحة عند إنشاء القائمة؛ لا توضع علامة الإنجاز لمجرد كتابة الكود.
- المنفّذ ينفذ الدفعات المحددة، والمشرف يراجع الملفات والناتج الفعلي والأدلة قبل إغلاق المهمة.
- مع كل مهمة مكتملة، أضف مرجع الدفعة والنسخة والصور أو نتائج الاختبار والمراجعة. الحالات التي لم يمكن اختبارها تُسجل غير متحققة مع السبب.
- أرقام المهام هنا تخص الواجهة؛ أرقام دفعات إصلاح التشغيل لا تعني إنجاز خطوات الواجهة.
- اربط أي مهمة جزئية بقائمة المكونات والصفحات المتأثرة؛ لا تغلق مهمة تشمل عدة صفحات بعد تجربة واحدة فقط.

## الثوابت المعتمدة

- عدد ملفات الصفحات المرجعي 58. تبقى الصفحات وروابطها ووظائفها بالعدد نفسه أو تزيد؛ أي حذف أو دمج لاحق يحتاج عرض الأسماء والروابط والسبب وموافقة المستخدم قبل التنفيذ. يشمل الحصر اللغتين ومسارات التفاصيل.
- ألوان البراند ودرجاتها الحالية محفوظة. الاتجاه البصري فخامة معمارية: حضور للشعار، صور مناسبة، عناوين قوية، مساحات محسوبة واستخدام مضبوط للذهبي.
- تختلف التكوينات بحسب وظيفة الصفحة: خدمات كفهرس واضح، فريق يبرز الصورة والخبرة، محتوى مناسب للقراءة، وإدارة تبرز العمل والجداول. لا تكرار لقالب كروت واحد أو مؤثر واحد عبر الموقع.
- إعادة صياغة النصوص بالعربي والإنجليزي تحافظ على الحقائق والخدمات والسياسات، دون أرقام أو شهادات أو وعود غير موثقة.
- الاختيار المسجل في الخطة هو Motion 13.1.1 للحركة وBase UI 1.8.0 لسلوك المكونات المعقدة، مع تنسيق خاص بالمكتب. هذه أرقام اختيارات الخطة، وليست ادعاء بتثبيتها أو اختبار توافقها؛ التحقق مطلوب قبل الإضافة.
- تبقى الحركة البسيطة في التنسيق الخاص حيث تكفي. React Bits مرجع لأفكار منتقاة؛ لا نقل بالجملة لقوالب جاهزة. لا محرك حركة إضافي مثل GSAP أوAnime.js ضمن النطاق الحالي.
- لا تغيير للأسعار أو الصلاحيات أو سياسة الحجز أو ربط البيانات بسبب إعادة التصميم. لا نظام حجز موازٍ.
- يظل أرشيف Stitch خارج الصفحات العاملة. إزالة Tailwind تأتي بعد انتقال كل الأجزاء العاملة.
- العربية والإنجليزية، واتجاه RTL، واللمس ولوحة المفاتيح، والموبايل والتابلت والكمبيوتر مشمولة. المظهر الفاتح والداكن للإدارة يتذكر اختيار الموظف في المتصفح.

## 1. الحصر وقرارات المكونات — قبل التعميم

- [ ] KMT-UI-001 — مطابقة قائمة الصفحات والروابط الفعلية مع المرجع، وتسجيل صور قبل التغيير وحالة كل صفحة، بما فيها التفاصيل واللغتان.
- [ ] KMT-UI-002 — حصر كل مكوّن مستخدم وأماكن ظهوره: التنقل، الأزرار، النماذج، النوافذ، الاختيارات، الجداول، البحث، التنبيهات، الحالات، الصور والأيقونات والمحتوى.
- [ ] KMT-UI-003 — إعداد قرار لكل مكوّن: تطوير الموجود أو استبداله أو تركيب الموجود لخدمة جديدة، مع السبب والبديل وتأثيره على الصفحات وخطة نقل الاستخدامات.
- [ ] KMT-UI-004 — ربط كل صفحة بمراجعة عنوانها ونصوصها وترتيب أقسامها بالعربي والإنجليزي، والحفاظ على الحقائق والسياسات والترجمات الحالية كمصدر.
- [ ] KMT-UI-005 — توثيق ألوان البراند والخطوط والمسافات والأحجام والحواف والأيقونات وحالات التركيز من النظام الحالي، وتحديد التوحيد المطلوب دون تغيير الهوية.
- [ ] KMT-UI-006 — التحقق من المصادر الرسمية والتوافق الفعلي وإصدارات Motion وBase UI وحجم التحميل قبل التثبيت؛ توثيق الاختيار وأي تغيير لازم قبل تعميمه.

## 2. التصور التفاعلي ومناقشة التغيير — خطوة 8

- [ ] KMT-UI-007 — تجهيز تصور للرئيسية يعرض التكوين المعماري والصور والنصوص والحركة القصيرة مع الأزرار المتاحة مباشرة.
- [ ] KMT-UI-008 — تجهيز تصور لصفحة خدمة يوضح ما تشمله والمعلومات أو المستندات المطلوبة والخطوة التالية، دون اختراع متطلبات غير موثقة.
- [ ] KMT-UI-009 — تجهيز تصور للحجز: المحادثة بجوار الملخص على الكمبيوتر، وملخص واضح قابل للفتح والتعديل على الهاتف.
- [ ] KMT-UI-010 — تجهيز تصور لحساب العميل يبرز الموعد القادم وما يحتاج إجراءً وتطور القضية والمستندات.
- [ ] KMT-UI-011 — تجهيز تصور للإدارة بالفاتح والداكن، يشمل الجداول والنوافذ والخانات والتنبيهات والبحث والإجراءات اليومية.
- [ ] KMT-UI-012 — تجهيز عرض تفاعلي للمكونات وحالاتها وحركتها ضمن مساحة معاينة، مع أمثلة الموبايل والكمبيوتر. لا يُحسب صفحة منتج جديدة إلا إذا كان ذلك مقصودًا.
- [ ] KMT-UI-013 — عرض التصورات على المستخدم وتسجيل مراجعته للتكوين والنصوص والحركة والقرارات المؤثرة قبل التعميم؛ توثيق المشكلة وتأثيرها والمقترح وطريقة التأكد من التحسن.

## 3. المكونات المشتركة بهوية المكتب — خطوة 9

- [ ] KMT-UI-014 — تطوير الأزرار والروابط وأزرار الأيقونات: العادي، المرور، التركيز، الضغط، التعطيل والانتظار، مع تسميات واضحة ومساحات لمس مناسبة.
- [ ] KMT-UI-015 — تطوير رأس الموقع والتذييل والقائمة الجانبية والتنقل ومسار الصفحة والتبويبات وقائمة الموبايل، مع حفظ الروابط والرجوع الصحيح واتجاه الحركة.
- [ ] KMT-UI-016 — تطوير النوافذ والحوارات والقوائم المنسدلة والأجزاء القابلة للفتح والتنبيهات الصغيرة، واستخدام Base UI حيث يلائم السلوك المطلوب مع تصميم KMT.
- [ ] KMT-UI-017 — تطوير خانات الكتابة والاختيارات ومربعات التأكيد والتواريخ والمواعيد ورفع الملفات، مع الملصقات والتحقق والأخطاء واستعادة الإدخال.
- [ ] KMT-UI-018 — تطوير الجداول والبحث والفلاتر والترتيب والتنقل بين النتائج والإجراءات، مع وضوح الكثافة والتعامل مع الشاشة الصغيرة والنصوص الطويلة.
- [ ] KMT-UI-019 — تطوير تكوينات الخدمات والفريق والمقالات ودراسات الحالة والصور والأيقونات والعناوين، بحيث يختلف العرض بحسب المحتوى.
- [ ] KMT-UI-020 — توحيد حالات الانتظار والفراغ والخطأ والنجاح وفقد الاتصال ورفض الصلاحية والتحميل الجزئي، مع إجراء واضح عند الحاجة.
- [ ] KMT-UI-021 — مراجعة مكونات المؤشرات والتقارير ومراحل المتابعة الموجودة وتطوير وضوحها، مع الحفاظ على مصادر الأرقام ودلالتها.
- [ ] KMT-UI-022 — تطبيق تنسيق مستقل للأجزاء المنقولة وربطها بالألوان والخطوط والمسافات المشتركة، وتغطية تفاصيل المظهرين في الإدارة.

## 4. الحركة — تُطبق مع المكوّن ثم تُراجع في الصفحات

| الموضع | سبب الحركة ووقت تشغيلها | المدة المستهدفة |
|---|---|---|
| افتتاحية الرئيسية | ظهور قصير للصورة والعنوان عند الدخول، دون تعطيل الأزرار | 600–800 مللي ثانية |
| أقسام التعريف | توجيه الانتباه عند ظهور القسم، مرة واحدة | 300–450 مللي ثانية |
| الأزرار والاختيارات | تأكيد الضغط واللمس والتركيز وتغير الاختيار | 120–180 مللي ثانية |
| القوائم والنوافذ | توضيح الفتح والإغلاق بصورة قابلة للمقاطعة | 180–260 مللي ثانية |
| الشات والملخص | توضيح دخول الرسالة وتبدل الخيارات والبيانات | 180–240 مللي ثانية |
| نجاح الحجز | علامة قصيرة بعد تأكيد التسجيل الفعلي | حتى 450 مللي ثانية |

هذه أهداف تصميم تُختبر داخل المشروع، وليست قياسات أداء تحققت بالفعل.

- [ ] KMT-UI-023 — توحيد مدد الحركة وطريقة بدايتها واستقرارها وتتابعها، وتسجيل غرض ومحفز وبديل هادئ لكل حركة.
- [ ] KMT-UI-024 — تنفيذ افتتاحيات وأقسام متنوعة بحركة محدودة، مع تمرير طبيعي ومحتوى أساسي ظاهر دون انتظار مؤثرات.
- [ ] KMT-UI-025 — تنفيذ استجابات الضغط والاختيار والفتح والإغلاق والتحديث داخل المكونات؛ تبقى جداول الإدارة والمبالغ والنصوص مستقرة وسهلة القراءة.
- [ ] KMT-UI-026 — تنفيذ حركة الشات وتحديث الملخص وتقدم الحجز والنجاح الفعلي؛ حركة الانتظار تعمل فقط أثناء انتظار حقيقي.
- [ ] KMT-UI-027 — اختبار نسخة الموبايل واللمس واتجاه العربي وإعداد تقليل الحركة؛ تقليل المسافات والزخرفة، وتحريك النص العربي ككتلة مقروءة دون تفكيك الحروف.
- [ ] KMT-UI-028 — قياس حجم الحركة الفعلي في التحميل الأول مقابل الميزانية المبدئية 25 كيلوبايت مضغوطة، وقياس السلاسة وتأثيرها على تحميل الصفحة. عند التجاوز تبسيط المؤثرات أو ما يُحمّل قبل التعميم.

## 5. تطبيق الحجز وصفحات الزوار — خطوتا 10 و11

- [ ] KMT-UI-029 — تطبيق الحجز الجديد بكامل رحلته: لغة الصفحة وتغييرها دون فقد الإجابات، كتابة حرة واختيارات، أسئلة عن الناقص فقط، مواعيد فعلية بتوقيت المكتب، ملخص قابل للتعديل، تأكيد صريح ثم نتيجة ورقم متابعة بعد التسجيل.
- [ ] KMT-UI-030 — تغطية تغيير الخدمة أوطريقة المقابلة وإعادة فحص السعر والموعد، ونفاد الموعد وإظهار البدائل، وتعطل الشات والشبكة وإعادة المحاولة دون مسح باقي البيانات، وإحالة الرأي القانوني المتخصص للمحامي.
- [ ] KMT-UI-031 — تطبيق الرئيسية بعد الحجز مع النصوص والتكوين المعتمدين ومقارنة قبل وبعد.
- [ ] KMT-UI-032 — تطبيق فهرس الخدمات وصفحات التفاصيل مع الحفاظ على الروابط والمحتوى الصحيح والوصول للحجز.
- [ ] KMT-UI-033 — تطبيق التواصل ونماذجه وحالات النجاح والفشل ومعلومات المكتب الموثقة.
- [ ] KMT-UI-034 — تطبيق الفريق وصفحات أفراده، مع الصور والخبرة والتخصص والمحتوى الفعلي.
- [ ] KMT-UI-035 — تطبيق المقالات ودراسات الحالة وقوائمها وتفاصيلها والبحث والتنقل داخل المحتوى الطويل.
- [ ] KMT-UI-036 — تطبيق الإعلام والخصوصية والشروط وبقية صفحات الزوار الموجودة في الحصر، دون إسقاط أي صفحة.

## 6. تطبيق حساب العميل والإدارة والصفحات المساعدة — خطوة 12

- [ ] KMT-UI-037 — تطبيق حساب العميل كاملًا: المواعيد والقضايا والمستندات والرسائل والملف والتفضيلات والحالات التي تحتاج إجراءً.
- [ ] KMT-UI-038 — تطبيق لوحة الإدارة والاستشارات والمواعيد والعملاء، مع وضوح البحث والإسناد والمتابعة والإجراءات اليومية.
- [ ] KMT-UI-039 — تطبيق القضايا والجلسات والتقويم والمهام والمستندات ومسارات تفاصيلها وإجراءاتها.
- [ ] KMT-UI-040 — تطبيق الرسائل والتنبيهات والماليات والتقارير والموظفين والأدوار والإعدادات والتدقيق وباقي أدوات المكتب المحصورة.
- [ ] KMT-UI-041 — تغطية الدخول والتحقق وإعداد الحساب والدفع والإيصال وصفحات الخطأ ورفض الوصول وبقية الصفحات المساعدة، مع حفظ العقود والروابط والسلوك.
- [ ] KMT-UI-042 — إكمال المظهرين الفاتح والداكن في كل تفاصيل الإدارة، وتذكر الاختيار على المتصفح واختبار النوافذ والقوائم والجداول والخانات والحالات فيهما.

## 7. إنهاء Tailwind والفحص والتسليم — خطوتا 13 و14

- [ ] KMT-UI-043 — نقل كل استخدامات التنسيق العاملة المتبقية والتحقق من تغطية جميع الصفحات والمكونات. إبقاء الأرشيف التاريخي خارج فحص التشغيل.
- [ ] KMT-UI-044 — حذف Tailwind وإضافاته وإعداداته غير اللازمة بعد اكتمال النقل، وفحص يمنع عودة الاعتماد القديم في الأجزاء العاملة.
- [ ] KMT-UI-045 — مطابقة قوائم الروابط والصفحات والمكونات قبل وبعد، بما فيها اللغتان والتفاصيل؛ أي نقص غير معتمد يمنع قبول الدفعة.
- [ ] KMT-UI-046 — تجربة عروض 390 و768 و1440 والنصوص الطويلة ولوحة مفاتيح الهاتف والمظهرين، وفحص التداخل والقص والتمرير الجانبي.
- [ ] KMT-UI-047 — تجربة لوحة المفاتيح وتسلسل التركيز ووضوح الأزرار والقراءة والتباين وقارئات الشاشة حسب الإمكان، واتجاه العربي وتقليل الحركة.
- [ ] KMT-UI-048 — إعادة تجربة الحجز والدفع والتعديل والتعارض والتكرار وانقطاع الاتصال وفشل الخدمة، وظهور النتيجة الصحيحة عند العميل والموظف؛ الخدمات الخارجية في بيئة تجريبية.
- [ ] KMT-UI-049 — إعادة فحص صلاحيات المستخدمين وفصل البيانات والملفات والمسارات المتصلة التي قد تتأثر بتبديل المكونات.
- [ ] KMT-UI-050 — مقارنة الشكل والسرعة قبل وبعد، وتسجيل الفرق بين محاكاة الأجهزة والأجهزة الحقيقية، وعدم اعتبار اختبار غير منفذ ناجحًا.
- [ ] KMT-UI-051 — استكمال دليل كل دفعة: المشكلة ومكانها وتأثيرها والتغيير وصوره ونتائج الاختبار ومراجعة المشرف والنسخة المرتبطة بها.
- [ ] KMT-UI-052 — إنهاء التقرير الجامع بما تم وما لم يمكن التحقق منه وسببه، وخطوات التحديث والرجوع، ثم التسليم وفق قواعد المشروع.

## ارتباط التنفيذ

تُنفذ المجموعات بعد جاهزية مراجعة التشغيل اللازمة، ويظل ترتيب الأولوية: البيانات والمال، ثم الحجز والعمل، ثم وضوح الاستخدام، ثم التحسين البصري. أي مشكلة خطيرة تظهر تتقدم في الأولوية.

لا يكفي نجاح البناء أوحفظ لقطة لإغلاق مهمة بصرية؛ يراجع المشرف الشكل الفعلي والتفاعل والأحجام المرتبطة بالمهمة. لا يقل عدد الصفحات أوتتغير سياسات العمل لمجرد تسهيل نقل المكونات.
